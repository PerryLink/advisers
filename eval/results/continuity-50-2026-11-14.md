# Continuity — 50 facts / 9 probes — 2026-11-14

Model: `deepseek-flash`, real CLI, throw-away `ADVISERS_HOME`. Script:
`eval/run-continuity.mjs` (`FACTS=50`). Each fact is stored with one
`advisers chat "<fact>"` call; then 9 generated probes ask about specific facts.

## Result (final harness)

**9/9 probes passed, 0 failures**, elapsed 506.8 s, exit 0.

Facts cover 10 categories (person/client/budget/project date/preference/
commitment/owner/company/email/deadline), 5 rounds each, deterministically
generated and duplicate-free.

## Harness findings during the run (recorded, not model failures)

1. First run scored 7/9; one failure judged only the first 300 chars of the
   answer, so a correct company name that appeared after `[tool]` trace lines
   was missed. The judge now runs on the whole answer after stripping tool
   traces.
2. Two failures were literal-token misses, not wrong answers:
   - expected `发报价`, model answered `向王工发送报价` (verb-stripped token added);
   - expected `先给结论`, model answered `结论先行` (synonym added).
3. A v2 run after the first fix scored 8/9; the remaining miss was the
   `结论先行` synonym. After adding it, v3 scored 9/9. No product/model change
   happened between these runs — only eval judging.

## Caveat

- 50 facts + 9 probes is a probe of long-context recall, not a 200-turn
  conversation soak. It does not exercise 200-turn compaction/summary drift.
- Facts are synthetic and unambiguous; real user messages are messier.
- One run only; treat it as evidence for this run, not a quality badge.
