# advisers

The cordis-only distribution of **Advisers** — a staff of AI advisers with one
continuous conversation, a user ledger, a commitment ledger, and reviewable
routines.

## Install

```sh
# 0.4.2 was published on 2026-11-22; npm @latest is now 0.4.2:
#   npm i -g --registry=https://registry.npmjs.org advisers@latest advisers-office@latest
# From checkout:
#   corepack pnpm install && corepack pnpm -r build
#   ADVISERS_OFFICE_LOCAL=1 node packages/advisers/bin/advisers.js status
# The `next` channel also points at 0.4.2:
#   npm i -g --registry=https://registry.npmjs.org advisers@next advisers-office@next
advisers soul init
advisers brief "做一份 Q4 预算 Excel，周五前给老板"
advisers chat "周五前把报价发给王工"
advisers office xlsx spec.json out.xlsx
advisers ls
advisers export
```

The CLI is a **local secretary runtime**: one REPL, a user ledger, a commitment
ledger, a routine ledger, Office artifacts, and an optional model loop. Without
an API key it records the session and can build/search files, but it does not
turn natural language into commitments or artifacts.

## Status

`0.4.2` was published on 2026-11-22 (npm `latest` = `0.4.2`; `next` is also `0.4.2`). It
is a patch on the 0.4.1 same-day follow-up: it adds manual fact entry (`fact add`, with a
required evidence quote and one-transaction supersede/KB-link/audit), the read-only IMAP
probe (`mail account test`), the explicit foreground `mail sync --watch`, the `sync pull
--dry-run` preview, the backup-age hint in `doctor --check-db`, a subcommand `--help`
consistency pass (usable before TOS acceptance) and the zero-model/zero-network
`pnpm eval:mail-local` quality gate (30 synthetic fixtures, wired into Linux CI), plus the
audit-driven documentation corrections. The 0.4.0 feature surface is unchanged: the local
knowledge base (schema v22), TLS-only IMAP mail entry, the interactive shell, proactive
urgent-first briefs, the policy/evidence 2.0 subset, receivables/payments with client
pack v2, MCP modern dual-era, Windows CI plus a portable ZIP, and the v2026.11.4 legal
revision. No new command requires a model call,
there is no background daemon, and `mail sync` is the one new explicit network path
(TLS-only, read-only, user-invoked). **Schema v22 is a one-way migration**: the CLI writes
`state.db.before-migrate-v*` before upgrading, a 0.3.2 binary opening a v22 database fails
with `E_SCHEMA_NEWER`, and downgrading means restoring that backup.
`0.4.1`/`0.4.0`/`0.3.2`/`0.3.1`/`0.3.0` remain installable by pinning but are superseded.
The runtime baseline remains the
"trustworthy delivery" line: per-item secrecy clearance on every egress surface, a local
audit tail anchor, backup rotation/verified restore and `doctor --repair`, 200k-row read
paths, MCP output caps plus legacy protocol negotiation, a read-only ledger facade, machine
readable contracts, a deterministic no-key eval suite and an SBOM gate. The `0.4.2` tarballs
are published from GitHub Actions OIDC/Trusted Publishing with SLSA provenance; verify with
`scripts/verify-release.mjs --version 0.4.2 --tag latest --sbom artifacts/sbom.cdx.json
--require-sbom` (the SBOM is generated by `pnpm run sbom`).
Release notes: <https://github.com/PerryLink/advisers/releases/tag/v0.4.2>. Model-backed KB
compile/ask, embeddings, the full PolicyGrant/exit 4–6 and DSH writes remain future work;
see the repository CHANGELOG for the full not-delivered list.
